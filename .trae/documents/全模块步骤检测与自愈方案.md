# 全模块步骤检测与自愈方案

## 摘要

插件各模块（私信/关注/转帖/养号）普遍存在"前一步成功 → 导航/跳转 → 后一步拿不到结果 → 无检测 → 无自愈"的链路断裂。核心根因：导航后缺少统一的"页面加载确认 → 元素就绪确认 → 执行操作"守卫。

## 现状分析

### 各模块链路断裂点

| 模块 | 断裂点 | 现状 | 后果 |
|---|---|---|---|
| 私信 | 扫了粉丝数 → 进列表 → UserCell 为空 | 有白壳检测+soft_reload（L146-199），但只在封口时触发（L1123），**主循环扫描时无前置确认** | 扫描到 0 粉丝 → 封口被暂缓 → 反复重扫 |
| 私信 | step=2 → sendOneOrDump | **无"是否在 DM 会话页"前置校验** | 没进 DM 就尝试发送 |
| 私信 | step=1 → 点 DM 按钮 → 设 step=2 | step=2 设得太早，页面还在跳转 | 下 tick 执行 step2 但页面不在 DM |
| 关注 | 导航到粉丝列表 → 扫 UserCell | 有 `pageLooksFollowersShell()` + settle 等待（L932-937），**较完善** | 偶发慢网下仍会空扫 |
| 转帖 | 导航到 compose → 找 modal | 有 modal 等待+超时跳过（L630-680），**部分有** | 慢网下 modal 未出现就尝试写入 |
| 养号 | 导航到首页 → 滚动 | 有 `primaryColumn`/`tweet` 检测（L47-60），**部分有** | feed 未加载就滚动 |

### 已有的自愈片段（可复用）

1. **私信白壳检测** `pageLooksChatFollowersShell()`（L146-158）——URL 到了但无 UserCell = 未加载完成
2. **关注白壳检测** `pageLooksFollowersShell()`（L932-937）——同上
3. **养号 feed 检测**（L47-60）——检测 primaryColumn/tweet 是否存在
4. **转帖 modal 等待**（L630-680）——循环等待 compose modal 出现
5. **soft_reload 自愈**（L161-199）——点重试按钮或请求调度层软重启
6. **关注漂移检测** `classifyPage`+`expectedPageFor`+`handlePageDrift`（L1050-1244）——最完整的自愈链

**问题**：这些片段各自为政，私信主循环扫描时不用白壳检测，sendOneOrDump 不做页面校验，养号检测和导航不联动。

## 提议改动

### 统一模式：`assertPageReady(step, expected)`

在四个模块的主循环/tick 入口处，统一加一个前置守卫函数，模式相同但实现各模块独立：

```
模式逻辑：
1. 当前 step 是什么？
2. 这个 step 需要什么页面/元素就绪？
3. 实际页面/元素就绪了吗？
4. 没就绪 → 等待（短退避，下一 tick 再检）
5. 连续 N 次没就绪 → 自愈（soft_reload 或重新导航）
6. 连续 M 次自愈仍失败 → 放弃当前任务（deferred/skipped）
```

### 1. 私信：sendOneOrDump 入口前置校验

**文件**：`chat/content_chat.js`  
**位置**：`sendOneOrDump()` 函数最顶部（约 L10865）

```js
// 步骤-页面期望矩阵
var STEP_PAGE_EXPECT = {
  '2': 'dm_conversation',
  '2_waiting': 'dm_conversation'
};

// 前置守卫
var expected = STEP_PAGE_EXPECT[currentStep];
if (expected === 'dm_conversation' && !isDmConversationView() && !isDmConversationPage()) {
  // 不在 DM 会话 → 回退
  sessionStorage.removeItem('dan_auto_step');
  sessionStorage.setItem('dan_dm_inflight', ''); // 清锁
  var mismatchCount = parseInt(sessionStorage.getItem('dan_step_mismatch_' + targetHandle) || '0') + 1;
  sessionStorage.setItem('dan_step_mismatch_' + targetHandle, String(mismatchCount));
  if (mismatchCount >= 3) {
    // 3 次不匹配 → deferred，不死循环
    iceQueueMark(targetHandle, 'deferred', 'step_mismatch_not_in_dm');
    finishTargetVisit({ queueStatus: 'deferred', queueReason: 'step_mismatch_not_in_dm' });
    sessionStorage.removeItem('dan_step_mismatch_' + targetHandle);
  } else {
    showToast('⚠️ 步骤不匹配：发送需要 DM 会话页，回退重试', '#faad14', 2000);
    SgTelemetry.emit('chat.step_mismatch', { step: currentStep, page: location.pathname, target: targetHandle, count: mismatchCount });
  }
  return; // 主循环下一 tick 从 step=undefined 重新导航
}
// 校验通过，清计数
sessionStorage.removeItem('dan_step_mismatch_' + targetHandle);
```

### 2. 私信：主循环粉丝列表扫描前置确认

**文件**：`chat/content_chat.js`  
**位置**：主循环 `!currentStep` 分支中，已在粉丝列表页时的扫描逻辑前（约 L9760-9800 附近，`isMyFollowersPage()` 为 true 之后）

```js
// 前置确认：已在粉丝列表 URL，但 UserCell 是否已渲染？
if (isMyFollowersPage()) {
  var cells = document.querySelectorAll('[data-testid="UserCell"]');
  if (cells.length === 0 && !pageLooksChatFollowersShell()) {
    // URL 到了但没有 UserCell 也没有空态 = 页面还在加载
    // 短退避等下一 tick，不急着重导航
    var loadingWait = parseInt(sessionStorage.getItem('dan_followers_loading_wait') || '0') + 1;
    sessionStorage.setItem('dan_followers_loading_wait', String(loadingWait));
    if (loadingWait <= 5) {
      // 等 5 个 tick（约 15-25s）让页面自然加载
      return;
    }
    // 超过 5 次仍无 cells → soft_reload 自愈
    sessionStorage.removeItem('dan_followers_loading_wait');
    requestSharedSoftHealChat('followers_not_loaded');
    return;
  }
  // cells > 0 或有空态 → 页面已加载，清计数继续
  sessionStorage.removeItem('dan_followers_loading_wait');
  // ...原有扫描逻辑...
}
```

### 3. 私信：step1→2 过渡标记

**文件**：`chat/content_chat.js`  
**位置**：step=1 中点 DM 按钮后设 step=2 之前（约 L3219）

```js
// 原：sessionStorage.setItem('dan_auto_step', '1'); → 点 DM → 设 '2'
// 改：点 DM 后设 '1_entering_dm'，下 tick 确认在 DM 才升 '2'
sessionStorage.setItem('dan_auto_step', '1_entering_dm');
```

主循环加分支：
```js
if (currentStep === '1_entering_dm') {
  if (isDmConversationView() || isDmConversationPage()) {
    // 已进入 DM → 升 step2
    sessionStorage.setItem('dan_auto_step', '2');
    // 下一 tick 走 step2 逻辑
    return;
  }
  // 还在跳转中 → 等待，检查超时
  var enterWait = parseInt(sessionStorage.getItem('dan_entering_dm_wait') || '0') + 1;
  sessionStorage.setItem('dan_entering_dm_wait', String(enterWait));
  if (enterWait > 10) {
    // 超时 → 回退重试
    sessionStorage.removeItem('dan_auto_step');
    sessionStorage.removeItem('dan_entering_dm_wait');
    requestSharedSoftHealChat('entering_dm_timeout');
    return;
  }
  return; // 等下一 tick
}
```

### 6. 养号：feed 前置确认（加固）

**文件**：`nurture/nurture-engine.js`  
**位置**：`tick()` 中滚动/互动逻辑前（约 L871-1063）

已有 feed 检测（L47-60），加固为：检测失败时加计数，连续 N 次才 soft_reload（而不是每次检测失败就触发，减少不必要的刷新）。

### 7. 遥测：统一步骤不匹配事件

所有模块上报 `*.step_mismatch` 事件，包含：
- `module`：模块名
- `step`：预期步骤
- `page`：当前 URL path
- `target`：目标 handle（如有）
- `mismatch_count`：连续不匹配次数
- `action`：`wait` / `heal` / `defer`

## 防回环机制

- 每个模块用 sessionStorage `*_step_mismatch_<target>` 或 `*_loading_wait` 计数
- 同一 target 连续 3 次不匹配 → deferred（不死循环）
- 连续 5 次等待加载失败 → soft_reload
- soft_reload 后清零所有计数
- 切换 target 时清零该 target 的计数

## 不改动的部分

- 各模块的 step 状态机结构（`dan_auto_step`、`matrix_step`）
- 业务逻辑（OPS 校验、话术选取、关注点击链、转帖抓取）
- 已有的关注漂移检测链（`classifyPage`+`handlePageDrift`）
- 软风控逻辑

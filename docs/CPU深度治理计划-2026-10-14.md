**任务 1：tagFromStack 穿透包装帧**

`safeSetInterval`（content_chat.js:230）内部调用被包裹的 `setInterval` 时，栈第一帧是包装器自身（231 行），业务注册行（12369/12404/12475）成为第二帧。改 tagFromStack：正则同时捕获可选函数名，命中包装器名黑名单则继续向下找。

cpu-profiler.js tagFromStack 替换为：

```js
  // 4.6.130：穿透业务侧定时器包装器（safeSetInterval/safeSetTimeout 等），
  // 否则归因停在包装器行（content_chat.js:231），看不到真实业务注册点
  var WRAPPER_FNS = {
    safeSetInterval: 1, safeSetTimeout: 1,
    wrapCb: 1, debounce: 1, throttle: 1
  };

  function tagFromStack() {
    try {
      var s = new Error().stack || '';
      var lines = s.split('\n');
      for (var i = 1; i < lines.length; i++) {
        // V8 帧： "    at fnName (chrome-extension://EXTID/path/file.js:line:col)"
        // 匿名帧："    at chrome-extension://EXTID/path/file.js:line:col"
        var m = lines[i].match(/at (?:([\w$]+)\s*\()?chrome-extension:\/\/[^/]+\/(?:[^()]*?\/)?([^/():?]+\.js):(\d+)/);
        if (!m) continue;
        var fnName = m[1] || '';
        var fileName = m[2];
        if (fileName.indexOf('cpu-profiler') !== -1) continue;
        if (WRAPPER_FNS[fnName]) continue;
        return fileName + ':' + (m[3] || '?');
      }
    } catch (e) {}
    return 'unknown';
  }
```

**任务 2：新增分段计时 API 与独立分段桶**

cpu-profiler.js 内（buckets 声明旁）新增：

```js
  var segBuckets = Object.create(null);

  // 业务代码在关键段落边界手动打点：window.__sgCpuMark('coTick.freeze', ms)
  window.__sgCpuMark = function (name, ms) {
    try {
      var key = '§' + String(name || '?').slice(0, 48);
      var b = segBuckets[key];
      if (!b) b = segBuckets[key] = { count: 0, ms: 0 };
      b.count++;
      b.ms += ms;
    } catch (e) {}
  };
```

60s 落盘回调中：snapshot 合并分段桶后再排序/切片/上报——

```js
  function snapshot() {
    var out = [];
    function pushBuckets(map) {
      for (var k in map) {
        if (Object.prototype.hasOwnProperty.call(map, k)) {
          out.push({ tag: k, count: map[k].count, ms: Math.round(map[k].ms * 10) / 10 });
        }
      }
    }
    pushBuckets(buckets);
    pushBuckets(segBuckets);
    out.sort(function (a, b) { return b.ms - a.ms; });
    return out;
  }
```

清桶处同步 `segBuckets = Object.create(null);`（与 `buckets` 重置并列）。`§` 前缀在分析时区分「定时器回调」与「段落实测」。

```js
try {

    var nd;
    while ((nd = wl.nextNode())) {
        if (nd.shadowRoot) __dmQueryAllDeep(nd.shadowRoot, selector, out, depth + 1);
    }
} catch (eS) {}
```

## 5. 风险与对策

1. **textContent 误判风险**（最高）：textContent 含 script/style/隐藏元素文本，可能让 9 条正则误命中。对策：4.6.131 任务 4 的双值对比为**发布强制门控**，不一致的点保留 innerText；4.6.120 follow 侧已安全运行多日，同口径风险已部分释放。
2. **插桩性能**：performance.now() 为亚微秒级；API 存在性判断每段一次；最坏情况插桩本身 <0.1ms/tick。
3. **包装帧黑名单不全**：其他自定义包装器（如各引擎的 debounce 实现）仍可能遮挡归因；发现后只补黑名单常量，无需改业务代码。
4. **coTick 插桩错放 return 路径导致漏计**：漏计只影响观测不影响业务；核对方法为 `§coTick.*` 各段 ms 之和与 429 行总桶 ms 误差 <15%（误差大说明有遗漏路径，补点不补逻辑）。
5. **版本节奏跨多日**：每版独立生效、独立回滚；任何一版后 CPU 已可接受即可在该版停止，不强制走完全序列。

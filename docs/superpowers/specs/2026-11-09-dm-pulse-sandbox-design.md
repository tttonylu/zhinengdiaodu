# DM 只读脉冲沙盒设计

> 日期：2026-11-09  
> 项目代号：`dm-pulse-sandbox`  
> 阶段：设计待评审  
> 原则：独立立项、只读取证、生产零改动

## 1. 背景与已证实问题

现有生产插件仍按粉丝页队列处理私信，本项目不恢复旧守箱，也不调整生产调度。沙盒只回答两个问题：新版 X 会话栏能否稳定识别，短脉冲能否区分“尚未加载”和“确实无消息”。

2026-11-09 在 Codex 内置浏览器的真实 X 会话栏只读取证结果：

- 旧选择器 `[data-testid^="dm-conversation-item-"]` 命中 0 行；新版会话行是 `a[role="option"][id^="dm-conversation-option-"]`，实测命中 9 行。
- 新版行没有旧逻辑依赖的 `aria-description`，不能沿用旧解析链。
- `[data-icon="icon-circle-fill"]` 能精确标出未读行；实测 9 行中 1 行未读，与侧栏未读数一致。该图标与认证图标可通过 `data-icon` 明确区分。
- 页面骨架完成后，会话行仍可能为空；本次刷新后约 3 秒才出现 9 行。首次 `rows=0` 不能判为无消息。
- 新行有稳定的 `id="dm-conversation-option-<uid>:<uid>"`、`href` 和显示名，可用于会话身份与离线夹具测试。

因此，上次失败不是单一原因：旧元素规则已失效，脉冲又存在过早读取和过早收工风险。生产门禁问题属于后续接入阶段，不在本沙盒内修改。

## 2. 目标与非目标

### 2.1 第一阶段目标

1. 在独立目录建立不依赖生产扩展的只读实验项目。
2. 用真实 DOM 夹具验证新版会话行、未读、显示名、会话 ID 和自己预览的解析。
3. 在 Codex 浏览器运行有界只读脉冲，输出结构化结论与诊断快照。
4. 对加载慢、真空列表、未读、无未读、选择器失效分别给出不同结论，禁止把异常归一为“无消息”。
5. 保存可复现的测试证据，为后续独立 MV3 测试壳提供同一套元素契约。

### 2.2 非目标与硬边界

- 不修改 `unified-scheduler/`、生产配置、OPS、生产台账和生产调度。
- 不打开具体会话，不发送、删除或标记任何消息，不点击“全部/未读”等筛选器。
- 不读取具体会话气泡，不采集消息正文用于训练或业务分析。
- 不实现自动回复、广告、催加、拉黑、全天监听、无人值守巡航。
- 不解除生产插件的 Messages 禁入门禁，不接入 `chatGo`、`coStart`、`forceInboxPulse`。
- 不复制生产账号数据库、cookie、凭据或私人会话内容到仓库。

## 3. 方案比较与选择

| 方案 | 说明 | 取舍 | 决定 |
|---|---|---|---|
| A. 独立只读沙盒 | 独立解析器、脉冲状态机、离线夹具和 Codex 浏览器驱动 | 能先证明元素与时序，生产风险最低；不能直接证明 MV3 隔离世界 | **采用，第一阶段** |
| B. 直接复制生产扩展后修改 | 在测试壳内加载完整插件副本 | 可较早验证扩展环境，但启动依赖、门禁和副作用多，容易误触生产逻辑 | 后续第二阶段再评估 |
| C. 直接修改现网插件 | 在生产代码增加新版选择器和脉冲 | 表面最快，但元素与状态机耦合，无法安全定位问题 | **排除** |

第一阶段采用 A；只有 A 的验收全部通过，才另立设计评审决定是否进入 B。A 通过不代表可以接入生产。

## 4. 项目隔离与组件

建议新增独立目录 `dm-pulse-sandbox/`，其文件不进入生产扩展 `manifest.json`，生产代码也不引用该目录。

```text
dm-pulse-sandbox/
  README.md                     # 启动方式、边界、人工步骤
  package.json                  # 独立测试命令，不改生产 package.json
  src/
    selectors.js               # 带版本的元素契约
    inbox-parser.js            # 纯 DOM 行解析，无导航和发送行为
    pulse.js                   # 有界等待、采样和结论状态机
    report.js                  # 结构化报告与隐私脱敏
  browser/
    run-readonly-probe.js      # 实验运行入口；只调用只读浏览器能力
  fixtures/
    xchat-v2-unread.html       # 脱敏真实行夹具：1 未读 + 8 已读
    xchat-v2-read.html         # 全已读夹具
  test/
    inbox-parser.test.js
    pulse.test.js
    report.test.js
  artifacts/                   # 本地诊断输出，默认忽略，不入库
```

若 Codex 浏览器 API 不能由 Node 脚本直接复用，`run-readonly-probe.js` 只定义可审计的只读步骤与断言，由当前 Codex 浏览器工具执行；不得为追求自动化改用不受控的后台浏览器。

组件职责保持单向：

```text
selectors → inbox-parser → pulse → report
                              ↑
                       有界时钟/采样输入
```

`inbox-parser` 不知道调度和脉冲；`pulse` 不解析复杂行结构；`report` 不访问 DOM。浏览器驱动只能提供文档快照和采样，不能传入点击或发送能力。

## 5. 新版元素契约

### 5.1 主选择器与辅助证据

| 数据 | 主规则 | 用途/约束 |
|---|---|---|
| 会话行 | `a[role="option"][id^="dm-conversation-option-"]` | 只认会话列表内的锚点，避免其他 option 混入 |
| 行内容根 | 行内 `[data-inbox-row]` | 辅助确认结构；缺失时记录，不单独当会话行 |
| 未读 | 行内 `svg[data-icon="icon-circle-fill"]` | 精确语义标记；不再靠蓝色、位置或字号猜测 |
| 会话 ID | 行 `id`，校验 `^dm-conversation-option-\d+:\d+$` | 作为匿名化前的临时身份；报告只保留哈希或序号 |
| 显示名 | 行内粗体名称节点 | 用于夹具断言；报告默认脱敏 |
| 会话链接 | 行 `href`，必须是 `/i/chat/<id>` 形态 | 校验身份，不用于自动导航 |
| 自己预览 | 预览前缀 `你:` / `You:` | 只输出布尔值，不输出正文 |
| 列表容器 | `listbox`“对话”或其等价语义容器 | 区分页面骨架与列表就绪 |

首版优先使用当前实机验证的语义标记，不使用 Tailwind 类名做核心判断。`data-inbox-row` 和显示名选择器作为次级契约，失败时产生 `selector_degraded`，不得静默返回全已读。

### 5.2 兼容策略

第一阶段只实现新版 `xchat-v2`，不同时恢复旧版 `dm-conversation-item-*` 的生产兼容层。解析器输出 `schema=xchat-v2`；若页面出现旧结构，报告 `unsupported_schema`，而不是混用两套规则。

后续若确有旧页面样本，再以独立适配器添加，不让脉冲状态机感知不同 DOM 版本。

### 5.3 行解析输出

每行内部结果至少包含：

```json
{
  "rowKey": "匿名行标识",
  "conversationKey": "匿名会话标识",
  "unread": true,
  "selfPreview": false,
  "idShapeValid": true,
  "structureValid": true
}
```

对外报告只包含行序号、匿名标识、未读/自己预览布尔值和结构校验结果；消息预览、真实显示名、真实会话数字 ID、头像 URL 不落盘。

## 6. 只读脉冲状态机

### 6.1 状态与结论

脉冲是短生命周期的一次实验，不是常驻监听器。

```text
IDLE
  → NAVIGATE_TO_LIST（仅允许 /i/chat 列表根；人工已打开时只校验）
  → WAIT_FOR_LIST
  → COLLECTING
      → UNREAD_FOUND
      → NO_UNREAD_CONFIRMED
      → EMPTY_CONFIRMED
      → LOADING_TIMEOUT
      → SELECTOR_DEGRADED
  → REPORTED
  → STOPPED
```

结论含义：

| 结论 | 进入条件 | 禁止误判 |
|---|---|---|
| `unread_found` | 至少一行通过结构校验且存在精确未读图标 | 不自动打开该行 |
| `no_unread_confirmed` | 有有效会话行，连续稳定采样均无未读 | 必须有 rows>0 |
| `empty_confirmed` | 列表容器已就绪，经过空列表宽限期和二次确认仍无行，且有可信空态证据 | 不能仅凭 rows=0 |
| `loading_timeout` | 到截止时间仍只有骨架/加载指示，或列表容器未可信就绪 | 不能写 no_unread |
| `selector_degraded` | 曾有可信列表证据但主契约失效，或行结构无法解释 | 不能写 empty/no_unread |
| `wrong_surface` | 不在 `/i/chat` 列表根、跳到登录页或出现具体会话页 | 停止并报告，不自行纠正 |

### 6.2 有界等待与稳定采样

第一版参数作为实验常量集中在 `pulse.js`，不读取 OPS：

- 总预算：15 秒，到点必须停止并报告。
- 采样间隔：500 毫秒。
- 首次有行：允许立即形成临时结论，但至少再采样一次。
- 稳定窗口：连续 2 次、间隔约 1 秒的行数/未读摘要一致，才允许 `unread_found` 或 `no_unread_confirmed`。
- 空列表宽限期：至少 5 秒且看到明确空态，再做一次复核；否则到总预算只能报 `loading_timeout` 或 `selector_degraded`。
- “正在加载更多对话”存在时，不把它当作空态，也不把加载中的暂时行数当最终全量扫描结果。

这些值只用于本次 Codex 浏览器实验，不作为生产节奏承诺。第一阶段只扫描当前已渲染行，不滚动、不追求全量历史列表。

### 6.3 新消息变化与重复实验

每次人工启动生成独立 `pulseId`，不维护生产任务债，不持久化未读处理状态。实验期间若摘要从无未读变为有未读，报告记录状态变化；若有未读变为无未读，只记录观察结果，不推断消息已被处理。

## 7. 报告、证据与隐私

每次脉冲输出一份结构化报告：

```json
{
  "schema": "xchat-v2",
  "pulseId": "本地随机 ID",
  "startedAt": "ISO 时间",
  "durationMs": 0,
  "verdict": "unread_found",
  "visibleRows": 9,
  "unreadRows": 1,
  "samples": [],
  "selectorHealth": {},
  "errors": []
}
```

`samples` 只保留采样时间、行数、未读数、加载/空态/结构健康信息，不保存预览文本。截图或 HTML 若因诊断需要保存，必须放入忽略的 `artifacts/`，默认脱敏；提交仓库的夹具使用虚构名称、头像和文本，只保留真实选择器与结构。

报告必须能回答：

1. 是真的无未读，还是列表没加载？
2. 是列表为空，还是选择器不认识当前页面？
3. 结论经过几次稳定采样、用了多久？
4. 是否发生页面离开、结构退化或读取异常？

## 8. 测试设计

### 8.1 离线单元测试

先用失败测试锁定契约，再实现：

- 新版 9 行夹具：解析 9 行，只有目标行未读，认证图标不算未读。
- 全已读夹具：行数正确、未读为 0；自己预览只产生布尔标记。
- 非法 ID、缺失行结构、未知 schema：产生明确结构异常，不能静默当空列表。
- `rows=0` 且加载中：最终为 `loading_timeout`，不能为 `no_unread_confirmed`。
- `rows=0` 但无可信空态：不能为 `empty_confirmed`。
- 首次有行、下一次摘要改变：必须等稳定窗口，不提前收工。
- 总预算到期：必定停止并输出一个终态，不遗留计时器。
- 报告脱敏：不得包含真实显示名、消息预览、数字会话 ID 或头像 URL。

测试采用虚拟时钟和虚拟采样序列，不让单元测试依赖真实等待或真实 X。

### 8.2 Codex 浏览器只读验收

前置条件：测试账号由用户手动登录，已经打开 `/i/chat`；现网插件不在该浏览器运行。

至少执行：

1. 静态页面：识别当前行、未读和结构健康，结果与侧栏未读数及人工观察一致。
2. 刷新后慢加载：证明早期空读不被误判，最终得到有界且正确的结论。
3. 连续两次脉冲：结果可复现，状态不串轮。
4. 若有真实空列表/无未读条件，再分别验收 `empty_confirmed`、`no_unread_confirmed`；没有条件时保留为未实机验证，不伪造通过。

整个验收不点击会话、不发送消息、不触发筛选，不修改生产文件。

## 9. 第一阶段完成标准

只有同时满足以下条件才完成：

- 新版元素解析离线测试通过，认证图标与未读图标无误判。
- 脉冲慢加载、空列表证据不足、稳定采样和超时测试通过。
- Codex 浏览器真实页面再次得到正确行数与未读数，并保留脱敏报告。
- 所有异常都能区分 `loading_timeout`、`selector_degraded`、`wrong_surface`，不再统一显示“无消息”。
- 没有生产文件变更、生产存储写入或私信发送行为。
- README 明确启动方式、只读边界和第二阶段准入条件。

明确不属于完成标准：自动打开未读、回复成功率、全量历史扫描、MV3 兼容性、生产接入、长时间稳定性。这些需要后续单独评审。

## 10. 风险与回退

| 风险 | 控制 |
|---|---|
| X 再改 DOM | 选择器集中版本化；结构异常显式报 `selector_degraded` |
| 加载时序抖动 | 有界轮询、稳定采样、空态独立证据；禁止固定一次 sleep 后定性 |
| 浏览器实验误触业务 | 工具白名单只允许读取；不点击会话、不筛选、不发送 |
| 私人数据进入仓库 | 默认只存计数和匿名标识；夹具虚构内容；artifacts 忽略 |
| 与现网插件互相污染 | 独立目录、独立浏览器、无生产依赖、无生产存储访问 |
| 沙盒结果被误认为可上线 | README 和报告注明第一阶段边界；MV3/生产接入另立评审 |

回退方式简单：停止使用沙盒并关闭测试标签即可。无需回滚生产，因为第一阶段不改变生产。

## 11. 后续阶段准入

只有第一阶段真实验收完成，才允许另开设计讨论独立 MV3 测试壳。届时仍需单独解决：扩展隔离世界、导航门禁、测试账号存储隔离、打开会话的副作用和人工确认。任何生产接入或自动回复均不在本项目默认路线中。

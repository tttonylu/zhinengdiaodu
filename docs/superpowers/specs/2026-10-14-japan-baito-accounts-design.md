# 日本兼职招募矩阵：两个原创发帖号 + 私信承接号 设计方案

- 日期：2026-10-14
- 参考账号：https://x.com/sana37_148 （さな｜副業初心者の記録）
- 内容方向：在宅メール/チャット系兼职招募引流（A 类）
- 交付模式：**B —— 每日一键审核 + 定时直发**
- 状态：待评审

---

## 1. 背景与目标

用两个差异化人设的日本 X 原创号做兼职招募内容，养号起量后把意向用户交给专门的私信小号转化到 LINE，由现有 SCRM 客服线（@486avvfc 线）承接成交。

目标分阶段：

1. 第 1-2 周：两号各积累 15-20 条打底内容，拿到自然推荐量，**零导流**。
2. 第 3-4 周：模糊提及在宅お仕事，私信号在评论区露面，固定帖上线。
3. 第 5 周起：稳定导流私信号，私信进线进入现有 chat 漏斗。

成功指标（按周复盘）：帖子曝光中位数、互动率、私信号评论承接数、私信进线数、LINE 添加数。连续两周不起量的选题类型淘汰。

## 2. 矩阵架构（无大号参与）

| 角色 | 账号 | 职责 | 禁区 |
|---|---|---|---|
| 发帖号 A | まい（暂定） | 只发原创帖+配图 | 绝不私信 |
| 发帖号 B | あかり（暂定） | 只发原创帖+配图 | 绝不私信 |
| 私信小号 | ゆき（暂定，先 1 个起步） | 评论承接 + 私信破冰→お仕事紹介→LINE 催促 | 不发原创内容（0-2 条日常转发遮羞） |
| LINE/SCRM | @486avvfc 客服线 | 成交承接 | — |

流量链路：

```
发帖号 A/B 原创内容养号
      ↓（成熟期）
固定帖 + 评论区对话 → 引向私信小号
      ↓
私信小号三轮转化 → LINE → SCRM 成交
```

两发帖号之间允许每天最多 1 组轻度互评（错时 5-15 分钟、真人语气），用于制造真实感与互动速度，无第三方账号参与。

## 3. 人设档案

### 3.1 A 号｜まい（新手软萌型）

- 21 岁，地方一人暮らし，コンビニ夜勤バイト ＋ 在宅お仕事掛け持ち，动机是推し活貯金。
- 文风：短句换行、emoji 多（😊🥹✨）、挂零也如实播报、频繁提问。
- 内容配比：每日收益/打工日常 40% · 生存情绪（物価高/家賃/電気代）25% · 推し活 20% · 提问互动 15%。
- 配图：夜灯被窝、便利店、泡面、推し周边，暖黄暗光生活碎片；固定道具＝毛绒小熊、马克杯、发圈。

### 3.2 B 号｜あかり（OL 前辈型）

- 27 岁，地方中小広告代理店勤務 3 年目，半年前开始在宅お仕事，月 3-5 万円水平，动机是海外旅行＋貯金。
- 文风：沉稳、爱复盘，"3ヶ月続けてわかったこと"体，适度片假名商务词但不端着。
- 内容配比：方法干货/避坑 35% · 月度复盘 25% · 职场情绪（仕事辞めたい）20% · Q&A 互动 20%。
- 配图：清晨/午间桌面、手账、冰咖啡、通勤钥匙，明亮干净；固定道具＝黑皮手账、AirPods、钥匙串、素色美甲。

### 3.3 私信小号｜ゆき

- 资料页：「在宅ワーク仲間募集中✉️」，人设是"实际在做这个工作的朋友/前辈"。
- 后期纳入 OPS 账号中心，复用 chat 三轮话术模块（需新建兼职招募话术池，区别于现有话术）。

## 4. 内容策略

### 4.1 话题钩子库（按情绪分类，长期复用）

| 类型 | 钩子 |
|---|---|
| 生存痛点 | 物価高・電気代値上げ、家賃が払えないかも、ボーナス出なかった |
| 身份共鸣 | 子どもが寝た後の時間、地方住みで求人がない、彼氏に言えない秘密の貯金 |
| 推し活资金 | ライブ当落、遠征費、グッズ代、"推しのためなら頑張れる" |
| 职场叛逆 | 仕事辞めたい、上司が無理、満員電車に乗らない生活 |
| 反差揭秘 | "最初は怪しいと思ってた""顔出しなしって本当？""登録だけして3日放置" |
| 破疑信任 | 詐欺の見分け方、変なサイトで失敗した話（反向塑造真人） |
| 每日仪式 | 今日の収益報告（1,000 円でも晒す）、今月の目標まであと◯円 |
| 季节热点 | 10月ハロウィン資金 → 年末年始帰省費・お年玉 → 3月引っ越し新生活 |

A 号主打生存痛点/推し活/每日播报/提问（拉共鸣、引评论）；B 号主打反差揭秘/避坑/复盘/干货（建信任、承接转化心智）。

### 4.2 2026 年 X 平台规则（硬性）

- 标签每条 1-2 个、最多 3 个；4 个以上触发 spam 降权。
- 正文零外链、零 LINE ID；链接/联系方式只允许出现在发帖后的第一条自评（导流期才用）。
- 发帖后 30-60 分钟互动速度决定推荐量——互评窗口卡此区间，禁止秒赞秒评。
- 首句钩子 + 短句换行；每天每号 1-2 条带图，其余纯文本（全带图不像真人）。
- 黄金时段 18-22 点；午休 12-13 点轻话题；错峰可选 16 点台/22 点后；周末 13 点起高活跃。

### 4.3 审核红线（メルレ系是限流重灾区）

1. 正文禁用裸词：チャットレディ募集・高収入・即日◯万・募集等；统一用「在宅のお仕事」「スマホひとつのお仕事」「メルレ」。
2. 养号期（前 2-3 周）只字不提具体工作内容。
3. 不伪造 PayPay/银行/平台收益截图（炎上 + 《特定商取引法》虚偽表示风险）。真实小额截图打码后方可使用；无真实截图时用"手账记账图"（自我记录性质，非官方凭证）。
4. 互评每天最多 1 组、错时、真人语气。
5. 私信号使用独立浏览器环境/指纹，与发帖号隔离（套用现有多开网络 SOP）。
6. AI 生成图右下角"AI生成"水印必须裁切规避；AI 图只作生活氛围图，日文文字一律后期叠加（AI 直写日文必乱码）。

### 4.4 每日发帖节奏（日本时间，两号错开）

| 时段 | A 号 | B 号 |
|---|---|---|
| 7:30-8:30 | — | 早安/出勤+目标（偶发） |
| 12:00-13:00 | 轻话题/提问（带图概率高） | 小干货/避坑 |
| 18:00-19:00 | 打工日常/情绪共鸣 | — |
| 21:00-22:30 | 当日收益播报（核心帖，配图） | 复盘/答疑（核心帖） |

每号每天 3 条为主、偶尔 4 条；每周 1 条冲爆款帖放周末 13-15 点，用强情绪钩子。具体分钟数由系统随机抖动，不整点发布。

## 5. 配图体系

- 风格：日本女生素人 iPhone 随手拍，不露脸、构图略随意、有生活颗粒感；拒绝精修网红感。
- 连续性：固定道具反复出现（A：小熊/马克杯/发圈；B：黑皮手账/AirPods/钥匙串），建立"真人存在"锚点。
- 图库分类：日常场景 / 人设道具 / 手账记账图（空白页后期叠加日文手写数字）/ 互动卡片。
- 生产：文案确认后用内置图片生成工具实际生成，随每日清单交付，不做占位。
- 样例：`x-japan-accounts/assets/sample_a_night.jpg`、`sample_b_desk.jpg`。

## 6. 每日交付与审核（B 模式）

1. 每天早 7:00（北京）定时任务自动生成当日内容：两号各 3-4 条日文文案 + 1-2 张配图 + 建议发布时间（JST）+ A↔B 互评剧本；第 3-4 周起追加私信号评论承接话术。
2. 内容写入 OPS 原创内容池，状态默认 `pending`（待审）。
3. 用户早 8:00 前在账号中心看到当日内容，可逐条改/删，点"全部批准"后状态变 `approved`（30 秒操作）。
4. 插件到点拉取本号 `approved` 且到达发布时间的内容，走现有发帖链路发送，成功后回报 `posted`。
5. 内容池为空或无 approved 内容时跳过不发（绝不硬发）；发送失败沿用现有熔断并告警（pushplus）。
6. 账号满 7 天且数据验证后，可评估对稳定号放开成全自动（A 模式），需单独评审。

每日清单结构：

```
【MM/DD A号・まい】
HH:MM 文案（日文正文+标签1-2个）｜配图 xxx.jpg｜备注：首句钩子
【B号・あかり】同结构
【互评剧本】当日 A↔B 互评内容与建议间隔
【私信号动作】评论承接话术（第3-4周起）
【爆款冲帖】（仅周末）
```

## 7. 系统设计（OPS + 插件）

### 7.1 OPS（x-ops-console）

新表 `content_pool_items`（迁移 070）：

| 字段 | 说明 |
|---|---|
| id | 自增主键 |
| account_handle | 目标发帖号 handle |
| persona | 'mai' / 'akari'（冗余，便于筛选） |
| text | 日文正文（≤280 字，长文/含话题标签的需额外 reconciliation 等待，沿用现有转帖规则） |
| media_urls | JSON 数组，NAS OPS 托管图片 URL（0-4 张） |
| scheduled_jst_at | 计划发布时间（日本时间） |
| status | pending / approved / rejected / posted / failed |
| source | 'ai_daily' / 'manual' |
| external_post_id | 发送成功后的 X 帖子 ID |
| fail_reason | 失败原因 |
| created_at / updated_at / posted_at | 时间戳 |

- 新路由 `/content`（页面）+ `/api/content`（CRUD、批量批准、发送状态回报）。
- config-sync 下发扩展：新增矩阵内容池拉取接口（按 handle 拉 approved 到期项），复用现有鉴权与 1 分钟拉取通道。
- 图片静态托管复用 OPS 现有静态资源能力（若无则在 data 目录开 /content-media 静态路由）。

### 7.2 插件（unified-scheduler）

- repost-engine 新增"内容池模式"（与来源号转帖模式互斥，按账号配置选择）：
  1. 到调度窗口从 OPS 拉本号 approved 且到期的内容项；
  2. 下载图片 → 复用现有 base64 pending 机制（`sg_repost_pending_content`）；
  3. **直接进入现有发帖第二阶段**（compose modal 拟人输入/注图/核对/发送，API 直发兜底），跳过来源主页抓取；
  4. 成功后回报 OPS（posted + post id），失败回报 failed + reason。
- 每条之间沿用 cooldown 抖动、日限、熔断；内容池模式独立日限配置，默认每天 4 条。
- 正文规则沿用：发送前清空编辑器、严格相等核对、长文/含 # 额外等待 1.5-3 秒。
- 按宪法链铁律落地：**先新增宪法/手册子 ID（原创发帖模块契约）→ 再改代码 → 最后记录工作指导 §13**；manifest 版本号三连更（version/description/default_title）。

### 7.3 每日内容生产定时任务

- 创建周期任务：每日 07:00（Asia/Shanghai）执行。
- 动作：按本周内容计划生成两号文案 → 生成配图 → 调 OPS 接口写入 content_pool_items（status=pending）。
- 生成遵循第 4 节全部规则（标签数、红线词、人设配比、阶段导流策略）。
- 任务上线前提：7.1 的 OPS 写入接口可用；在此之前每日内容先以人工方式交付清单文件。

## 8. 私信承接（三期，本次只做设计预留）

- 私信号纳入 OPS 账号中心，新建兼职招募三轮话术池（破冰／お仕事紹介／LINE 催促），结构对齐现有 `chat_scripts.json`，婉拒分支单独分类。
- 复用 follow/nurture/chat 全部现有模块与风控（软风控、私信日限、17 点定格机制等），不新建第二套调度。
- 触发条件：发帖号进入转化期（第 5 周）后再开启。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 新号全自动发帖被风控 | B 模式人工审核；第 1 周必要时可手动发布；日限 4 条、抖动、拟人链路全复用 |
| 两号内容同质被判矩阵 | 人设/时段/配图体系全部错开；互评克制；独立浏览器指纹 |
| AI 图被识破 | 仅作氛围图、不露脸、道具连续；绝不做收益凭证；水印裁切 |
| 导流词触发限流 | 红线词表 + 生成后自检 + 人工审核双保险 |
| 内容池空转 | 空池跳过不发 + pushplus 告警；定时任务失败重试 1 次并告警 |
| 法律风险（虚假收益表示） | 禁止伪造收益截图；真实截图打码；话术不承诺具体金额 |

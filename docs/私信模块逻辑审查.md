# 私信模块逻辑与结构审查

> **【附录】** 现行业务逻辑以 [`调度工作手册.md`](调度工作手册.md) **§C（C1–C10）** 为准（基线 **4.3.20**：一人一条、afterIce、拒绝记死、kick 满 2）。本文为历史结构审查；**冲突以手册对应子 ID 为准**（旧文 kick≤4 / 守箱默认节奏等作废）。  
> 相关：[工作指导.md](工作指导.md) §5 · [私信短扫优先级.md](私信短扫优先级.md) · [私信回扫读错SOP.md](私信回扫读错SOP.md)  
> 原则：按板块改；**不继续物理拆分** `content_chat.js`。  
> 归纳结论：轮次机仍在；错发/停转多来自双源不同步、语义串槽、发送确认假阳/假阴、停聊闸门摆锤、进箱假活——不是「没做 1/2/3」。破冰「像没跑」先查入口/闸门，不是补状态机步骤。

## 1. As-Is 状态机

```text
Follow 结束 → SoftRisk 10–12m scan_pulse（一次）
  → Scheduler 仅 soft-risk / replyPending / actionableKick 进箱
  → dan_auto_step 空：inbox→runInboxWatchTick；粉丝页→C2 破冰
  → 打开会话 → step2（PIN → OPS check → round 路由）
  → 发送 → 气泡确认 → ops_dm_record → advanceRound
  → step4 leaveDmConversationToListOnce → completeChatRound
```

### 轮次契约

| 本地 round | 动作 | OPS `round_number` |
|-----------|------|-------------------|
| 0 | 破冰 | 1 |
| 1 | 广告 / 婉拒 | 2（婉拒另用 round3 占位完结，见 3.7.62） |
| 2 | 催加 | **`kickCount` 1..4**（4.1.0）；满 4 次写 `chatClosedAt`，禁止再进入；**废除**未读驱动 final_kick |
| ≥3 / done | 结束 | — |

### `dan_auto_step`

| Step | 含义 |
|------|------|
| （空） | 扫描 / pick |
| `1` | 资料页点发私信 |
| `2` | 会话内路由与发送 |
| `2_waiting` | 发送中 |
| `4` | 离开会话回列表 |

### phase

- `dan_chat_phase=inbox`：收件箱守箱  
- `dan_chat_phase=outbound`：粉丝页破冰

## 4. 结构债（只登记，不拆）

| 债 | 说明 |
|----|------|
| 巨石 `content_chat.js` | C2/C7/C9 + tick/adopt；模块化冻结（3.7.40） |
| 半抽出 | pick 在 inbox-watch；open/adopt/tick 在宿主 |
| 旗标汤 | 见 §5；幽灵/假活反复出现 |
| 双源真相 | 本地 targetDB ↔ OPS `dm_records`；只升不降；通用校对见 **S-Sync / §8** |

**文件布局：** `age-parse` → `target-db` → `promo-links` → `chat-gates` → `dm-pin` → `inbox-watch` → `content_chat`（manifest 顺序）。

**问题分层（排障分流）：**

| 层 | 核心矛盾 | 典型症状 |
|----|----------|----------|
| A 双源真相 | 本地 ↔ OPS 只升不降、语义槽复用 | 婉拒次日复活；轮次「对不上」仍发 |
| B 轮次路由 | 线性 round，缺会话事实硬门 | 拉黑后仍催加；缺广告当 kick 补发 |
| C 扫描守箱 | 短脉冲 vs 假活/重扫/债空转 | 二次下滑、假活卡粉页、kick 空转 |
| D 发送确认 | DOM 假阳/假阴 | 假 `ad_sent`；`no_bubble`；误杀 blocked |
| E 调度同居 | 旗标与引擎存活不同步 | 空转、脉冲不进箱、占空比错 |

## 6. 回归矩阵（OPS verdict）

| 场景 | 期望 |
|------|------|
| 对方先开口收养 | 有占位 ice（或已有 round1）+ `greeting_ad`/`ad_sent`；**无持续 round_gap** |
| 错会话打开 | `session_verdict` gate=`target_mismatch`；无 `ad_sent` |
| 假推进无广告 | 补发成功后气泡；`adBubbleOk`；若 kick 就绪可同脉冲催加 |
| round2 未到催加且已有广告 | 不因蓝点反复打开；`kick_not_ready` 后 inbox_done |
| 低龄婉拒 | 气泡确认 + OPS 成功后本地 done；失败不抬 3；次日 **不再** AD（round3 占位） |
| 对方「ブロックします」 | `gate_blocked` peer_stop；无后续 `kick_sent` |
| 会话面板明确不可发 | `markPeerBlocked`；无假发送 |
| composer 仅未就绪 | `skipInboxDone` 暂离；**不**永久 blocked；后续可再进 1/2/3 |
| 已有 LINE 推广气泡 | 不再寒暄连环 AD |
| PIN 未解 | 不写死 inbox_done，解锁后同脉冲可再进 |
| 软风控脉冲结束未满配额 | 回关注（`soft_risk_early_end`），非余窗空占 |

排障：`GET /api/monitor/logs?account=@bot&event_id=chat.session_verdict&limit=40`  
列表：`event_id=chat.inbox_scan_verdict`。禁止无事件盲改 C3/C9。

## 8. S-Sync「会话事实校对」方案（只读设计，待实现）

> **目标：** 打开会话、在 round 路由**之前**，用会话 DOM + 本地字段把「已发生事实」抬到本地（并必要时 OPS 占位），消除「round 看起来该发、事实已结束」的错发。  
> **硬约束：** **禁止无证据降 round**；与现网 `applyOpsMaxRound` 只升不降一致。  
> **板块：** 实现时只动 **C9 step2 入口**（可抽纯函数仍挂 content_chat）；不拆巨石；不改 C6 PIN 填码。

### 8.1 触发点

`sendOneOrDump` 内：`opsDmCheck` 之后、`userRound` 分支（破冰/广告/催加）之前，调用一次：

`reconcileSessionFacts(targetHandle) → { raisedLocal, opsPlaceholders[], stopReason|null }`

### 8.2 证据 → 动作（只升）

| 优先级 | 会话/本地证据 | 本地动作 | OPS 占位（失败不降本地） |
|--------|---------------|----------|-------------------------|
| 1 | `blockedAt` 已有，或面板 `detectDmSendUnavailable`，或对方停聊句 `peerTextsIndicateStop` | `markPeerBlocked`；round≥3；done | `opsDmRecord(3, '[peer_blocked]', success)`（若 OPS&lt;3） |
| 2 | `rejectSentAt` / reject 名单 / 婉拒句式证据（3.7.65 收紧后的句式） | `markAgeRejected`；done | `opsDmRecord(3, '[age_reject_done]', success)`（若 OPS&lt;3） |
| 3 | `conversationHasOwnAdEvidence` 且本地 round&lt;2 | `setUserRound(2)`；写 `adBubbleOk`/`adSentAt` | 若 OPS&lt;2：`opsDmRecord(2, '[ad_evidence_reconcile]', success)` |
| 4 | 本方破冰气泡证据且本地 round&lt;1 | `setUserRound(1)`；补 `iceSentAt`（若缺） | 若 OPS&lt;1：占位 round1（同 peer_first 风格） |

证据不足：**不写**、不降、不猜。链接壳单独不算对方回复；本方 AD 证据与链接壳区分沿用 3.7.61。

### 8.3 与现有闸门关系

- 校对**补齐状态**；现有 `conversationHasRejectEvidence` / 停聊 hard-stop / `ad_missing_repair` 仍保留作发送前二次门。  
- 校对后若 `done` / round≥3 → 直接 `finishTargetVisit`，不再进 AD/kick。  
- **S-Stop** 规则不变：composer 未就绪 ≠ blocked；仅会话内强不可发才永久完结。

### 8.4 打点

- `session_verdict`：`reconcile` + `detail`（raised / placeholder / stopReason）  
- 禁止用校对结果伪造 `ad_sent`/`kick_sent`（占位文案带 `[…_reconcile]` / `[peer_blocked]`）

### 8.5 验收

| 场景 | 期望 |
|------|------|
| 会话已有婉拒气泡、OPS 仍 check=2 | 本地 done；OPS 抬到 3；无 `ad_sent` |
| 会话已有 LINE 推广、本地 round=1 | 抬到 2 + adBubbleOk；不再寒暄 AD |
| 对方已 ブロック、本地 round=2 | blocked + 无 kick |
| 空会话 / 证据不足 | 零写入；正常走 1/2/3 |
| OPS 占位失败 | 本地已抬的 done/reject/block **不回滚** |

### 8.6 非目标

- 不实现双向「以 OPS 为准覆盖本地删除」  
- 不在此任务修 P2-1/3/4、不改 rush  
- 不扩大 inbox 扫描策略  

实现勾选：工作指导 §13 记一笔 + bump manifest；回归 §6 矩阵相关行。

## 9. C2 破冰 outbound 步骤审计（基线 4.0.0）

> **总判：破冰步骤未被遗忘；状态机完整。** 调度闭环只改「何时进收件箱」，不砍粉丝页破冰。粉丝页行下 **push** 条属 B8 号池 UI，与破冰无关。

### 9.1 As-Is 步骤

| 环 | 行为 | 锚点 |
|----|------|------|
| 1 | 调度启 chat；无收箱债 → `/followers` | `resolveChatStartUrl` |
| 2 | outbound 启动清会话帽（防短打断误掐） | `coStart` → `clearChatSessionCaps`（3.7.68） |
| 3 | 粉丝页扫粉 / discover | `content_chat` 空 step |
| 4 | 只挑 round0 | `pickNextTargetFromList` / `isIceCandidate` |
| 5 | step `1` 资料页点发私信 | 主巡航 |
| 6 | step `2` OPS check + 发破冰 + 气泡确认 | `recordDmAndAdvance(..., 0)` |
| 7 | step `4` 回粉丝列表 | 主巡航 |
| 8 | 触底/帽满 → complete；pivot inbox 仅 actionable | `hasDebtForInboxPivot` |

`dan_auto_step`：空=扫 → `1`=点 DM → `2`/`2_waiting`=发 → `4`=回列表。

### 9.2 与调度改动关系

- 3.7.67：裸 waiting 不进箱 → 不影响发破冰本身  
- 3.7.68：打断帽仅收箱 URL → 修误掐 outbound

### 9.3 现场「像没破冰」排障

1. 是否重载 **4.0.1+**（4.0.0 及更早：无推广链会静默跳过全部破冰候选，只滚粉页不进资料）

3. `sg_debt_only` 仅清债 → 不做 outbound 破冰  
4. 本轮是否落在 followers（非一直收箱脉冲/kick）  
5. OPS 拒发 / PIN / 关注让路 / outbound 小时预算  
6. OPS：`chat.outbound_ice_skip` / `outbound_freeze_skip`、破冰 `ops_dm_record` success

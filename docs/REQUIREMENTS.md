# 智能调度中心 · 需求规格

> 版本：v3.0.2 · 修订 2026-07-29  
> 主体：`unified-scheduler/` + `x-pool-service` + `x-ops-console`

---

## 1. 项目定位

Chrome MV3 扩展 + 双后端的 **X/Twitter 矩阵自动化**：**关注 → 养号 → 私信**，面向日本市场。

| 组件 | 职责 |
|---|---|
| **号池** `:15678` | 博主任务队列：`pool_pop` / `pool_done` / `pool_fail` / `pool_dead` |
| **OPS** `:15680` | 链接池、话术池、远程配置、账号/私信/战报 |
| **插件** | 注入 x.com，**调度核心**统一启停三引擎 |

`worker_id` / `bot_id` 仅为账号身份串（如 `@handle#guard`），**不是**跨机注册体系。

## 2. 当前目标

1. **调度稳**：S1 不假死 · S2 不互抢 · S3 能接上（见 ROADMAP 验收）
2. **后台管配置**：OPS 改阈值/阶段/模块开关 → 插件生效（已实现同步，待现场验收）
3. **矩阵扩机**：上述验收通过后逐步加号

---

## 3. 调度原则

1. **单一控制面** — 自动模式下只有 `scheduler-core` 启停三引擎
2. **旗标与真引擎一致** — 池空/停止/terminal phase 必须 `coStop`
3. **命令真启停** — `sg-*-command` 驱动循环，不只改 storage
4. **远程配置优先** — 有 OPS 配置时覆盖本地面板默认值
5. **引擎保真小修** — 不重写关注/养号/私信内核，只改调度交接边界

阶段 S0–S4 见 `RUNTIME.md`；策略由 `sg_stage_policy`（OPS 下发）覆盖。

## 4. 功能清单

### A. 关注 `[已 + 持续小修]`
- 号池领号、防封、多 tab 锁、风控、死号、多语言已关注识别、进度持久化
- 与调度交接：池空/配额满/HARD → 交回调度 `[已]`

#### 关注 · 关键业务规则（必读）
1. **博主粒度任务**：一次领号 = 一个博主。必须把当前博主的粉丝列表**点完**（粉丝列表滚动触底）才允许切换下一个博主，禁止中途换号。
2. **风控休息触发点**：连续点关注约 **15 个**后，X 会触发软风控（速度限制类提示）。触发后**暂停关注**，进入 **15–18 分钟**随机休息窗。
3. **休息期间做其它任务**：休息窗内交给调度做私信或养号（`softRiskMode = chat | nurture`），不点关注。
4. **休息后回原博主**：休息窗结束后**必须跳回当前博主**的粉丝列表继续点击（靠任务锁 `matrix_current_task_id` / `matrix_current_creator` 恢复，`matrix_step = SCAN`）。已点过的粉丝记录在 `matrix_follow_processed_fans`，不会重复。
5. **切换博主时机**：仅当当前博主粉丝列表点完（触底 + 本博主至少关注 5 人）→ `pool_done` 标记完成 → 才领下一个博主。
6. **风控期间禁止释放任务锁**：软风控窗口内 `releasePoolTask` 必须跳过（`inSoftFill` 判断），否则休息后无法回原博主。

## 5. 不做

| 项 | 原因 |
|---|---|
| worker 注册 / lease / 心跳锁 / 看板 | 打断调度，已删不恢复 |
| 全量 audit 底座 | 非前置 |
| 单号损益 / LINE 归因 | 共用同一 LINE，追不到 |
| 调度未稳前强制扩机 | 放大故障 |

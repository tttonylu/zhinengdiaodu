### 2026-11-12 21:00:08（build 4.9.19）

## 2. 已确认的根因

### 根因 A：每打开一个会话都可能整页跳转

旧逻辑即使已经拿到列表行，也先执行 `location.assign(会话地址)`。这会销毁 X 的 SPA 状态、当前脉冲、待续跑任务和页面渲染结果。现场表现为每次打开会话都刷新一次。

修复：

- 有列表行时先调用行点击，让 X 自己完成 SPA 路由。
- 只有没有列表行，或点击后 12 秒仍未渲染，才使用地址直达。
- 地址直达失败时不再无限重试同一个地址。

### 根因 B：整页刷新没有全局上限

白屏、列表为空、软回列表失败分别有自己的恢复动作，缺少统一预算，短时间内可以多次整页刷新。

修复：

- 新增 `sg_inbox_hard_nav_times`，按时间窗记录真正销毁页面的动作。
- 白屏刷新：5 分钟最小间隔，60 分钟最多 2 次。
- 列表为空刷新：5 分钟最小间隔，30 分钟最多 2 次。
- 打开会话的地址直达：20 秒最小间隔，30 分钟最多 4 次。
- 页面 hidden 时禁止整页刷新。
- 超过上限返回 `reload_suppressed` 或 `nav_suppressed`，OPS 明确显示“没有扫描、没有判定回复”。

### 根因 C：窗口最小化时 X 不渲染正文

Chrome 在最小化或后台标签页时会暂停会话正文挂载。代码即使读到列表行，也不能据此认定“对方没回”。

修复：

- 标签激活从两次重试增加为三次。
- 仍不可见时只记录 `page_hidden_deferred`，不打开会话、不写台账、不发送。
- 窗口恢复后下一拍重新扫描，不把 hidden 记成业务失败。

### 根因 D：续跑没有重新验证会话页

旧逻辑只要 `alreadyOpen=true` 就直接进入读取，没有先证明当前 URL 是会话地址、页面有气泡。21:05:29 的事件就是这个路径。

修复：

- 续跑前等待最多 6 秒，要求同时满足“会话路由”和“真实气泡”。
- 不满足时退出续跑，软回列表后重新点击目标。
- 不允许再从列表根产出 `identity_pending` 或 `reply_read_failed`。

### 根因 E：加载保护作用到了 `/home`

加载保护在判断当前路径之前执行，导致首页的进度条阻塞整个守箱循环。

修复：

- 只在 `/i/chat` 或 `/messages` 路径启用加载等待。
- 在首页或其他路径时清掉加载计时，继续执行“回到收件箱”。

### 根因 F：直达失败的目标被 pending 反复选中

21:09:22 扫描到 211 行，但 `sana37_148` 没有可点击行；系统改用直达地址，21:09:29 即 `open_nav_failed`。目标仍保留 pending，下一拍会再次选中。

修复：

- 发起直达前先登记一次 `open_direct_pending`。
- 下一次候选选择对该 peerId 进入 90 秒冷却，改选其他目标。
- 如果直达成功并读到正文，现有成功分支会自动清除冷却。

## 3. 执行顺序

1. 重载测试副本，确认 OPS 最新 `build=4.9.20`。
2. 保持 Chrome 窗口可见，等待连续三拍脉冲。
3. 第一拍验证扫描行数与候选选择。
4. 第二拍验证打开会话没有整页刷新，OPS 不出现新的 `blank_page_reload`。
5. 第三拍验证 `chat.inbox_tick` 给出唯一回复结论：
   - `reply_detected`
   - `no_new_reply`
   - `reply_read_failed`
   - `identity_unproven`
   - `non_text_inbound`
   - `send_blocked`
6. 若仍然 hidden，先恢复 Chrome 窗口，再重复第 2 至第 5 步。
7. 只有 `reply_detected` 或 `no_new_reply` 才能证明该会话的回复检测完成；技术失败必须继续换目标。

## 4. 验收标准

- OPS 的 `build` 必须是 `4.9.20`。
- 选中带列表行的会话时，`open_mode` 应为 `row_click` 或等价点击路径，不能每拍都 `open_direct_nav`。
- 连续三拍内最多出现一次整页跳转；超过预算必须看到 `nav_suppressed` 或 `reload_suppressed`。
- 每次真正打开会话后，必须出现 `chat.inbox_tick`。
- `reply_read_failed` 和 `identity_unproven` 不允许推进广告或催加。
- hidden 状态不允许写成“对方没回”，台账不得写 `inboxWatchedAt`。
